# 核心业务逻辑

## 模块职责

- `src/domain/buffet.ts`：纯业务函数。输入普通数据，返回计算结果或新状态，不访问 Vue、uni、本地存储、当前时间或随机数。
- `src/store/buffet.ts`：响应式状态和流程编排。负责生成会话 ID、获取时间、调用业务函数以及读写本地存储；对页面的接口保持不变。
- `src/data/menu.ts`：菜品目录，分类查询委托给业务模块。
- 页面和组件：交互、导航、文案与样式。结果页使用统一的小票构建函数，进度组件和小票使用统一的回本判断。

## 点餐到保存的流程

1. 开始用餐：以票价、模式和 ID 创建活动会话，清空待选菜品和历史轮次。
2. 加减菜品：`selected` 用商品 ID 记录数量；减到零就删除该项。通过菜品目录得到待选明细，未知 ID 不参与结算。
3. 计算价值：本轮价值为单价乘数量的合计；展示价值为已提交轮次价值加本轮待选价值。
4. 点单完毕：提交非空轮次，保存时间、价值和菜品快照，随后清空待选。空轮次不提交。
5. 查看结果：合并已提交轮次与待选明细，生成预览。预览本身不会提交待选，也不会改变会话。
6. 结束用餐：先提交仍在待选的菜品，再生成独立记录快照。始终保存到点餐明细；选择收藏时同时保存到小票夹。最后重置会话并持久化。

## 计算与保存规则

- 差额 = 已吃价值 − 门票价格。
- 回本百分比 = 四舍五入（已吃价值 / 门票价格 × 100），票价为零时百分比返回零。
- 已吃价值达到票价判为回本；达到票价的 60% 判为接近回本；其余判为未接近回本。
- 进度条的 70% 位置表示回本，属于展示规则，继续由进度组件处理；实际百分比可以超过 100%。
- 历史菜品按名称合并数量，保留首次出现的单价；轮次价值独立保存。此处沿用现有规则，尚未引入按商品 ID 合并或价格变化处理。
- 相同会话 ID 的记录原位更新，新记录插到列表最前面。
- 累计差额、轮次数和菜品数均基于点餐明细，不依赖是否收藏小票。
- 小票预览中的待选菜品参与总价值和汇总明细，但尚未进入 `rounds`；正式保存前提交它们，保证记录完整。

## 持久化边界

沿用 `buffet-session-v2`、`buffet-records` 和 `buffet-receipts` 三个存储键。读取失败使用默认值；缺少点餐明细时沿用已有小票作为初始记录。此改动不迁移存储数据，也不改变既有异常处理。

## 验证

`npm test` 覆盖数量变化、小数价格、空轮次、预览汇总、快照隔离、按 ID 更新、历史统计、回本边界、分类筛选，以及状态层结束用餐与持久化的完整流程。`npm run type-check` 检查页面与模块的类型衔接。
